## 12. Admin actions failed after 15 min ("Authentication is required") — fixed

Approving a claim (and any admin action) failed with "Authentication is required" a while after
login. Root cause: the admin access-token cookie `maxAge` is **15 min** (== API `JWT_ACCESS_TTL`)
and there was **no refresh** — the 30-day refresh token was never used, so once the access cookie
expired every action 401'd. Fix in `apps/admin/src/middleware.ts`: when the access cookie is gone
but the refresh cookie remains, `POST /auth/refresh` once (single place — refresh tokens rotate,
so refreshing in two places would revoke the family), set the new pair, and **inject the fresh
access token into the current request** so an action posted right at expiry also works. On a
spent refresh token it drops the cookies so the console shows sign-in.

**Codex (admin UI) — separate finding:** the Users / Listings / etc. console pages are
**read-only** — they display rows but expose no management ACTIONS (suspend/reinstate user, change
role, moderate/remove listing, verify business…). The API endpoints all exist and are
permission-gated (`user:suspend`, `listing:moderate`, `business:verify`, …); the pages just need
the action buttons wired to them. Now that the auth-refresh above is in, those actions will work.

## 10. Admin console Google sign-in — didn't redirect — fixed

Reported: signing in with Google (an approved super-admin account) didn't redirect. Diagnosed:
account IS `SUPER_ADMINISTRATOR` (`*`), client-ids match (admin `NEXT_PUBLIC_GOOGLE_CLIENT_ID` ==
api `GOOGLE_CLIENT_ID`), no "Rejected a Google token" in the api logs — so the auth _succeeds_.
The bug was the client redirect: the Google path used `router.replace()` (soft nav) which **races
the session cookie the server action just set** — the destination is fetched before Set-Cookie
lands, the middleware sees no session and bounces to `/login`. (Email/password worked because it
exits via a server `redirect()` = hard nav.) Fix: `window.location.assign(redirectTo)` — a hard
navigation that carries the cookie. `apps/admin/src/app/login/google-console-sign-in.tsx`.

### The "~₹9,000" figure — reconciled

That was the hypothetical cost of LLM-**generating** a unique bilingual description for all
4.2M businesses. LocZ does **not** do that: `businesses` has no Te/Hi columns — descriptions are
**composed at render** (`describeBusiness`) from shared, transliterated building blocks
(city / locality / landmark / category names). So the only Sarvam spend is transliterating those
shared blocks — a few thousand names, mostly already done. Real remaining spend ≈ low hundreds of
₹ (the two ₹100 credits cover the 100k-cell landmark head; localities run on the original key).
